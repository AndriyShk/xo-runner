# Публікація та оновлення

## Коротко про варіанти

| | Автооновлення | Що потрібно від нас |
|---|---|---|
| **Chrome Web Store** | так, Chrome сам тягне нову версію | акаунт розробника ($5 одноразово), рев'ю 1–3 дні |
| Свій сервер + `update_url` | **не працює** | Chrome із 2018 не дозволяє встановлювати розширення поза Store на Windows і macOS |
| Роздати zip, «Load unpacked» | ні, кожен оновлює руками | нічого, але потрібен Developer mode у кожного |

Тобто якщо ми хочемо саме **щоб оновлення прилітали людям самі — це тільки Chrome Web Store**. Інших робочих шляхів на macOS/Windows немає.

## Разова підготовка

1. Зареєструвати акаунт розробника: https://chrome.google.com/webstore/devconsole — $5 одноразово, платить власник акаунта.
2. Пройти верифікацію email.

## Публікація

```bash
./build.sh
```

Створює `dist/xo-pulse-runner-<version>.zip` — його і завантажувати. Скрипт заразом перевіряє синтаксис усіх скриптів, валідність `manifest.json` і наявність іконок, щоб не отримати відмову на дурниці.

Далі в Developer Dashboard: **New item** → залити zip → заповнити картку (текст нижче) → **Submit for review**.

## Оновлення

1. Підняти `version` у `manifest.json` — Chrome оновлює тільки якщо версія зросла. Формат `1.0.0` → `1.0.1` (фікси) → `1.1.0` (нові механіки).
2. Дописати рядок у `CHANGELOG.md`.
3. `./build.sh`
4. У Dashboard: **Package → Upload new package** → Submit.

Після схвалення Chrome підтягне нову версію користувачам сам протягом кількох годин.

## Обґрунтування дозволів (це питають на рев'ю)

- **`storage`** — зберігає налаштування користувача (розмір, темп, режим, увімкнено/вимкнено). Нічого, крім цих налаштувань, не пишеться.
- **Host permission `https://xo.market/*`, `https://beta.xo.market/*`** — розширення працює тільки на сторінці графіка цього сайту: читає пікселі canvas, щоб знайти лінію, і малює поверх власний прозорий шар.
- **Remote code:** немає. Увесь код у пакеті, нічого не завантажується ззовні.
- **Збір даних:** ніякого. У формі Privacy практики позначити всі пункти як «not collected».

## Скриншоти

Потрібно 1–5 штук, рівно 1280×800 або 640×400.

Знімати краще з `test/sandbox.html` — там та сама механіка на згенерованому графіку. З реального сайту знімати не варто: у шапці видно баланс акаунта.

```bash
python3 -m http.server 8777
# відкрити http://localhost:8777/test/sandbox.html
```

Що показати: персонаж на схилі лінії, стрибок через бар'єр, момент щучки, попап із налаштуваннями.
